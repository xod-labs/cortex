# 🚀 Cortex v1.6.0 — We Apologise for the Inconvenience

> *"We apologise for the inconvenience."* — God's Final Message to His Creation, in *So Long, and Thanks for All the Fish*.
>
> An interface puts an inconvenience on every person nobody pictured while building it: the one on a keyboard, behind a screen reader, at 400 % zoom. This release gives the team someone whose job is to picture them — an accessibility specialist, with what accessible UI is made of, how to check it without slowing a pull request, and two workflows. It also apologises for inconveniences of Cortex's own: a Cursor rule that Cursor would read only when asked, a `cortex sync` that blamed a link on someone else, and the last notes on `cortex upgrade --commit`.

## The accessibility specialist

A new role, `engineering/accessibility-specialist`, says with evidence whether a person who cannot see, hear, hold a mouse or read small grey text can complete the task an interface was built for. It audits against WCAG 2.2 AA, or the standard a law imposes on the project. It reviews designs before they are built, says how each finding was obtained and what was not tested, and **never states a conformance level from a tool's results**.

It is cast as **Prak** in h2g2, the witness who can only tell the whole truth, and as **Walter White Jr. — Flynn —** in breaking-bad, who knows first-hand what was built without him in mind.

| Card | What it carries |
|---|---|
| `practices/web-accessibility` | What accessible UI is made of: native semantics before ARIA, the keyboard, focus, forms, contrast pairs, target size, reflow, structure, alternatives, live regions, motion — the WCAG 2.2 additions marked |
| `testing/accessibility-testing` | Which check runs where. Lint, HTML validation and component axe on the pull request; browser scans on a schedule, never on its required path; a baseline that only shrinks |
| `design/open-design` | The first `design/` card: mockups rendered by [Open Design](https://github.com/nexu-io/open-design) from a versioned design system, held to accessibility criteria, handed off as a component map |
| `engineering/accessibility-audit` | A workflow from the frame to the statement: the automated baseline, the manual audit, the remediation backlog, the regression harness, the cadence |
| `product/target-mockup` | The first `product/` workflow: brief, design-system contract, mockups, accessibility review, validation, hand-off |

The Lead Frontend aims at WCAG 2.2 AA, and loads the practices card. The standard a law imposes — RGAA in France, EN 301 549 in the European Union, Section 508 in the United States — stays out of Cortex: a project declares its own `compliance/accessibility-{jurisdiction}` card in its overlay tier.

A request to *audit the accessibility* of a site is what the audit workflow answers, the specialist first.

## Cursor reads the bootstrap ([#306](https://github.com/xod-labs/cortex/issues/306))

Cursor's documentation says a rule with `alwaysApply: false`, no `description` and no `globs` applies only where a chat @-mentions it. `.cursor/rules/cortex.mdc` had no frontmatter at all, which Cursor reads the same way — inferred from that documentation, and to be checked in a real conversation ([#137](https://github.com/xod-labs/cortex/issues/137)). A new conversation in Cursor would not read Cortex's bootstrap. The file now opens on:

```yaml
---
description: Cortex - the AI team's bootstrap, read first
alwaysApply: true
---
```

`cortex upgrade` writes it again in a rule nobody changed. One a team changed is kept, with a note: `cortex init --force` writes it, or you add the frontmatter yourself.

## `cortex sync` and a checkout that is gone ([#303](https://github.com/xod-labs/cortex/issues/303))

A `cortex/` that `cortex sync --link --from` linked to a checkout since moved or deleted was refused as *a link Cortex did not make*. The refusal now says the checkout is gone, and what to do: remove the link, then `cortex sync --link --from` the checkout's new path, or `cortex sync` for the pinned version. The assistant's rule for a spec that is gone says the same, link mode kept.

## `cortex upgrade --commit` ([#304](https://github.com/xod-labs/cortex/issues/304))

- **A file outside the git work tree** — a bootstrap linked to a shared file — is named where it is, with the link that leads there, and stays in what the project must commit: to commit where it is.
- **The work tree is found by what it is, not by how its path is spelt.** On macOS, a project's path typed in another case put every file outside the work tree, and nothing was committed. For a project in a directory below the top, it could hide a change of yours to `cortex.toml` from the snapshot, and `--commit` could commit it.
- **The tests the counter-review of 1.5.0 asked for**, each one now catching the mutant it was written for.

## Upgrading

1. Update the binary: `cortex self-update`.
2. Move your projects: `cortex upgrade --all --dry-run`, then `cortex upgrade --all` — or `cortex upgrade` in one project. A known tool's bootstrap that Cortex wrote with its marker (1.4.0 and later) and nobody changed is written again, with the rule that keeps link mode for a checkout that is gone; a Cursor rule nobody changed also gets its frontmatter. Any other — a `--tool custom` file, one an older Cortex wrote without the marker — may be kept: `cortex init --force` with the options it was written with — the same `--tool`, `--workspace` in a workspace, `--instructions-file PATH` for `--tool custom` — writes it again and keeps yours as `.bak`.
3. Commit `cortex.toml`, `cortex.lock` and the bootstrap files written again — or let `--commit --message MESSAGE` do it.
