# 🚀 Cortex v1.8.7 — Almost, but Not Quite, Entirely Unlike Tea

> *"The Nutri-Matic Drinks Synthesizer had produced a plastic cup filled with a liquid that was almost, but not quite, entirely unlike tea."* — *The Hitchhiker's Guide to the Galaxy*
>
> Without git, Cortex reads a `.gitignore` almost, but not quite, entirely like git does. This release says so plainly, rather than pretending to be git. It also closes the edge cases 1.8.5 left open: special files that still held a command, and the update a source checkout names.

A patch. Nothing is added to the `cortex` command: no command, option, key or format.

## Special files are said, never waited on ([#386](https://github.com/xod-labs/cortex/issues/386))

1.8.5 taught most commands to say that a path holding a named pipe, a socket or a directory is not a file. A few paths were left:

- **`cortex.toml`** is now said not to be a file by `cortex config`, `cortex project add` and `cortex init` too. `cortex config` printed the machine's keys as if outside a project; `cortex init` wrote over a pipe, and failed half-way on a directory.
- **A loop of links** at `cortex.toml`, `cortex.local.toml`, `cortex.lock` or the team's lock is refused like a pipe. A link that leads nowhere at `cortex.local.toml` is still replaced, as before.
- **`cortex/.git`, `cortex/.synced` and `~/.cortex/projects.toml`** are read without waiting. A named pipe there held `cortex sync` or `cortex validate` for good.
- **`cortex upgrade --commit`** checks the ignore and attributes files git reads before it writes anything — each folder's `.gitignore` and `.gitattributes` from the top of the work tree down, `info/exclude`, `info/attributes`, and git's own `core.excludesFile` and `core.attributesFile`. A named pipe there let the upgrade write its pin, then wait in `git status` with no end. It is now named first:

  ```
  cortex upgrade: /home/you/work/.gitignore is not a file, and git, reading it as an ignore file, would wait on it: remove it, then run the command again
  ```

- **`cortex upgrade`** no longer writes `cortex.toml` and puts it back when it refuses `cortex.local.toml`: it refuses first, and the file is untouched.

Each message names what to remove, and each test runs that remedy.

## The update a source checkout names reads the checkout ([#379](https://github.com/xod-labs/cortex/issues/379))

From a source checkout, a command that finds this cortex too old names how to update it. That was `git -C CHECKOUT pull`, or `pull origin HEAD` on a detached HEAD, whatever the checkout. It is now read from the checkout's own files — never by running git:

| The checkout | What is named |
|---|---|
| a branch with an upstream | `git -C CHECKOUT pull` |
| a detached HEAD, a branch with no upstream — none set, a remote not declared, or a branch of the checkout itself — or a reftable repository | `git -C CHECKOUT pull REMOTE HEAD`: the branch's remote, else `origin`, else the first remote declared |
| no `.git`, as an extracted source archive, a HEAD git refuses, or no remote | the install script of the version, as from a binary |

The path and the remote are quoted for the shell the command is shown for, POSIX or PowerShell: a `$` or a backtick in a path is no longer expanded.

## Without git, `.gitignore` is read on purpose like this ([#391](https://github.com/xod-labs/cortex/issues/391))

Where git cannot answer — none on `PATH`, or a repository git refuses — Cortex reads each folder's `.gitignore` itself, only for the exact line it would add. It matches no pattern, sees no folder ignored whole, and reads a negation on a path's last part. Every difference with git goes one way: Cortex may add a line git would not need, and never leaves out one git needs.

Matching every rule of git was weighed and left: Cortex is not git. [Getting started](../docs/getting-started.md) now says what the reading does, including its one visible effect: `cortex.local.toml`, a line with no `/`, also ignores a nested project's `cortex.local.toml`. Tests compare the reader with `git check-ignore` on 2,600 cases to keep it one-way.

## An underlined entry is a heading ([#398](https://github.com/xod-labs/cortex/issues/398))

The changelog reader, which numbers a checkout's development version and gates a release, read an entry's text underlined with `===` or `---` as the entry. CommonMark makes it a heading in the item, so a 💥 there marks no major. The reader now agrees with commonmark.js 0.31.2 on these forms, and Cortex's own CHANGELOG reads the same at every revision. 1.8.6 named this as its one difference left.

ADR-008, ADR-009 and ADR-010 record these changes in their amendments.

## Upgrading

`cortex self-update`, then `cortex upgrade 1.8.7`, or `cortex upgrade --team 1.8.7` for a team's file. A project that stays on 1.8.6 keeps working.
