# 🚀 Cortex v1.8.5 — In Much the Same Way That Bricks Don't

> *"The ships hung in the sky in much the same way that bricks don't."* — *The Hitchhiker's Guide to the Galaxy*
>
> A named pipe where Cortex expected a file could make a command hang — for 30 seconds a question, or with no limit at all. This patch makes Cortex say what it found instead, and repairs, by itself, the store a user who is not root could not repair.

Nothing is added to the `cortex` command: no command, option, key or format.

## The store repairs itself ([#384](https://github.com/xod-labs/cortex/issues/384))

- **A stored version that holds less than its three trees is written again.** `cortex sync`, `cortex init` and `cortex upgrade` remove it, the way `cortex prune` removes a version, and write or download it again. The store is read-only, so the removal Cortex used to name failed for a user who is not root, and on Windows. That held for the store's refusal and for `cortex validate`'s `LOCK_DIGEST` alike.
- **`LOCK_DIGEST` names the sync alone** — `cortex sync --locked` during a try — and never a removal, which a race with `cortex prune` could make pointless.
- A link or a file a user put at a version's name is refused and named, never followed or removed.

## Named pipes, directories, and other files that are not files ([#358](https://github.com/xod-labs/cortex/issues/358))

- **An ignore file above the project that is a named pipe** — a `.gitignore` higher in the repository, `.git/info/exclude`, `core.excludesFile` — made each `git check-ignore` wait 30 s: about 85 s for `cortex sync`, and `cortex upgrade --branch` and `--commit` failed. Git is now asked once per repository and command. After a wait, the project's own `.gitignore` files answer. `upgrade --commit` still waits in `git status`, as git itself does ([#386](https://github.com/xod-labs/cortex/issues/386)).
- **A named pipe at `.gitmodules` or at the instructions file** (`CLAUDE.md`, …) no longer holds `sync`, `validate` or `init`. Cortex says it is not a file.
- **A `cortex.toml`, a lock or a `cortex.local.toml` that is not a file** is said to be one, with its remedy. It used to be called missing, or failed halfway through a write.
- **A directory at `.gitignore`** no longer stops `cortex init` halfway. Nothing is written to it, and the note says it is not a file.
- **A renamed team's folder that is a file, a pipe or a socket, or a link to one,** is named as such, as the default `agents` is since 1.8.4.
- **The runtime** logs a `cortex.local.toml` whose kind it cannot tell, a loop of links for one, once per error.
- **A copy** is no longer given the link's advice about the final slash.

## Ignore files without git ([#355](https://github.com/xod-labs/cortex/issues/355))

- **Without git, a folder's own `.gitignore` is read as git reads it.** A `.claude/.gitignore` holding `!settings.local.json` now outranks the root's line, where Cortex used to take the root's word alone.
- **With git, `/.cortex-sync-*` is written again below a negation** that takes back a real staging folder. Cortex used to ask git about a stand-in name, which the negation did not match.

ADR-008 and ADR-010 record these changes in their amendments.

## Upgrading

`cortex self-update`, then `cortex upgrade 1.8.5`, or `cortex upgrade --team 1.8.5` for a team's file. A project that stays on 1.8.4 keeps working.
