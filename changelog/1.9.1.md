# 🚀 Cortex v1.9.1 — Brain the Size of a Planet

> *"Here I am, brain the size of a planet, and they ask me to pick up a piece of paper."* — Marvin, *The Hitchhiker's Guide to the Galaxy*

> A whole release to hold a name. The core's distribution name was free on PyPI, and anyone could have taken it: this one is ours, reserved before anything announces it.

A patch. Nothing changes in the `cortex` command, the spec or a project's files.

## The core's name is ours on PyPI ([#86](https://github.com/xod-labs/cortex/issues/86))

The command and the runtime depend on the core by its distribution name. They install it from `../core`, but a `pip install` without it looks for that name on PyPI, where it was free: whoever registered it first would have had their code installed into the process that holds the API keys.

- **The core is distributed as `xodlabs-cortex-core`.** `cortex-core` could not be reserved: PyPI refuses it as too close to `cortexcore`, another project. The command and the runtime depend on the new name; the core is still imported as `cortex_core`.
- **`.github/workflows/pypi.yml` reserves it**: run by hand from `main`, approved by a maintainer in the `pypi` environment, it publishes a placeholder, `0.0.0`, that installs nothing, through PyPI's trusted publishing, with no token stored.
- **A test holds it**: the core's name, the packages that depend on it, and the workflow reading it from `core/pyproject.toml`.

ADR-007 records the new name in its amendments.

## Upgrading

`cortex self-update`, then `cortex upgrade 1.9.1`, or `cortex upgrade --team 1.9.1` for a team's file. A project that stays on 1.9.0 keeps working: nothing it reads has changed. A development install runs `pip install -e ../core` again, so that pip records the core under its new name.
