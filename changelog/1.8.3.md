# 🚀 Cortex v1.8.3 — Anything That Happens, Happens

> *"Anything that happens, happens. Anything that, in happening, causes something else to happen, causes something else to happen."* — *Mostly Harmless*
>
> The configuration cascade of 1.8.1 had its edge cases, and its reviews had made more of them. This patch closes the ones about remedies, `cortex upgrade`'s git repositories, the team's folder, the bootstrap and the runtime. Each remedy a message names is now one that works, and each test runs the remedy it checks.

The `cortex` command adds no command, option, key or file format. Only messages, remedies and one rule of the bootstrap change.

## Remedies that work

- **A source checkout too old for a project names its own update** ([#345](https://github.com/xod-labs/cortex/issues/345)): `git -C <checkout> pull`, not `cortex self-update`, which a checkout refuses.
- **`cortex validate` names the sync that puts a try's team spec back** ([#346](https://github.com/xod-labs/cortex/issues/346)): during a try, `LOCK_DIGEST` names `cortex sync --locked`. A plain sync moved to the try's version and repaired nothing.
- **A team's folder that is a link leading nowhere, or that cannot be searched** ([#350](https://github.com/xod-labs/cortex/issues/350)): the link is named, with its two remedies, for the default and a renamed folder. `cortex init` beside a folder this user cannot search names `chmod u+rwx agents`.

## `cortex upgrade` and the team's repository

- **A resume's `--branch` is made where its files are written** ([#347](https://github.com/xod-labs/cortex/issues/347)): in `agents/` when its file and lock are the only ones written, and nowhere, saying so, when they are in no work tree. The project's repository no longer gets an empty branch.
- **`--all --team` compares each follower's bootstrap with the version it read** ([#348](https://github.com/xod-labs/cortex/issues/348)), as the first project's is, so a bootstrap without a marker is written again for every project alike.
- **A team's folder linked to no repository is committed nowhere, and is said so** ([#351](https://github.com/xod-labs/cortex/issues/351)): by `--team`, `cortex sync`, a resume and a resume during a try. They no longer name a commit in `agents/`.

## The registry and `cortex validate`

- **`cortex project list` and `cortex prune` beside a team's file that does not read** ([#349](https://github.com/xod-labs/cortex/issues/349)): `PINNED` is `-` unless a committed `cortex.toml` pins the version, and `prune` keeps what the project reads now.
- **`cortex validate --service` warns of a service the runtime refuses** ([#353](https://github.com/xod-labs/cortex/issues/353)) — `SERVICE_REFUSED` — and checks none of it. A warning, so only `--strict` fails on it.

## The bootstrap and the runtime

- **A `cortex/` link to the store names its version** ([#352](https://github.com/xod-labs/cortex/issues/352)). With `sync = "link"` and no `synced`, a teammate's move of the pin now leads the assistant to `cortex sync`. `cortex upgrade` writes the new rule into every bootstrap nobody changed.
- **The runtime refuses a `cortex.local.toml` that does not parse** ([#344](https://github.com/xod-labs/cortex/issues/344)) with a `422` carrying the CLI's own message, where it used to read the file as absent.

ADR-013 §9 records these changes to its contract. The README says what the assistant does without `synced` ([#356](https://github.com/xod-labs/cortex/issues/356)).

## A commit budget ([#367](https://github.com/xod-labs/cortex/issues/367))

[`docs/process/adr-implementation.md` §10.6](../docs/process/adr-implementation.md#106-the-commit-budget): a release gets 30, 60 or 100 commits that are not merges, by its size. There is one commit per review finding, no merge inside a stack but the pull requests' own, and an accepted ADR's text is frozen. 1.8.0 had made 380 such commits, and 131 merges.

1.8.3 is the first release delivered under the rules of 1.8.2 and these: size **M**, so 3 review passes and 60 commits.

## Upgrading

`cortex self-update`, then `cortex upgrade 1.8.3`, or `cortex upgrade --team 1.8.3` for a team's file. A project that stays on 1.8.2 keeps working. A team on 1.8.2 can try this release on one machine first: `cortex upgrade --local 1.8.3`.
