# 🚀 Cortex v1.8.6 — Who Is This God Person Anyway?

> *"'Oh dear,' says God, 'I hadn't thought of that,' and promptly vanishes in a puff of logic."* — the Babel fish argument, in *The Hitchhiker's Guide to the Galaxy*, which Oolon Colluphid made the centrepiece of his bestseller
>
> Oolon also wrote *Who Is This God Person Anyway?* A fresh `cortex init` left a newcomer asking much the same of the team: whom to call. It now names them — Oolon first, as the prompt manager. Two tools behind the release cycle also learn to read what they were missing: the changelog's Markdown, and a branch's older protection.

A patch. Nothing is added to the `cortex` command: no command, option, key or format.

## `cortex init` names whom to call ([#149](https://github.com/xod-labs/cortex/issues/149))

`setup.sh` used to end an install with the theme's aliases. Since 1.0.0, `cortex init` did not. It now ends with them again, read from the active theme's `characters.md` through the cascade, so a team's own theme is read as well:

```
Theme h2g2: @Oolon, the prompt manager, takes every request and calls the expert it needs.
Or call one yourself: @Slartibartfast (architect), @Hactar (lead-backend), @Eddie (lead-frontend), @Marvin (security-engineer).
The whole team: /home/you/.cortex/versions/1.8.6/agents/personalities/h2g2/characters.md
```

Nothing is printed with no personality, nor from a `characters.md` whose table does not read whole — a prompt manager and at least four experts. `cortex init` never fails for its hint. A wrong hint is never printed. Printing the hint when `cortex sync` changes the theme needs the theme recorded in `synced`, which is a new key; that half is [#397](https://github.com/xod-labs/cortex/issues/397), for 1.10.0.

## The changelog is read as CommonMark reads it ([#354](https://github.com/xod-labs/cortex/issues/354))

A source checkout and a development build number their version from the changelog's `[Unreleased]` entries, and the release gate reads the same file. The reader now follows CommonMark in more cases:
- **indented code** is no entry's text, so a 💥 in it marks no major;
- **an item's own line** holding a heading or a break is no paragraph to go on;
- **a quote** is read with what its lines above left open in it;
- **HTML blocks of `<pre>` and of block elements** hold no section, heading nor entry.

It was compared with commonmark.js 0.31.2. Outside the forms it still declares unread, one difference is left: a setext underline below an entry's text, which CommonMark makes a heading ([#398](https://github.com/xod-labs/cortex/issues/398)). Cortex's own CHANGELOG reads the same at every one of its revisions.

## `setup-release` reads a classic branch protection ([#235](https://github.com/xod-labs/cortex/issues/235))

A classic protection that requires checks on `main` or a line — `N.x` — makes GitHub wait for them besides the rulesets'. `bin/setup-release.sh` read rulesets only, so `--check` said every setting held. It now reports such a protection and leaves its removal to you. `xod-labs/cortex` has none.

ADR-009 records the reader and the protection in its amendments.

## Upgrading

`cortex self-update`, then `cortex upgrade 1.8.6`, or `cortex upgrade --team 1.8.6` for a team's file. A project that stays on 1.8.5 keeps working.
