# 🚀 Cortex v1.8.1 — Never Could Get the Hang of Thursdays

> *"This must be Thursday," said Arthur to himself, sinking low over his beer. "I never could get the hang of Thursdays."* — *The Hitchhiker's Guide to the Galaxy*
>
> 1.8.0 merged on Thursday 2026-11-12, and its release run failed before its draft. No release, tag or binary is named 1.8.0, and its number is spent. This patch publishes 1.8.0's content, unchanged.

## What 1.8.0 holds

The team's file, `agents/cortex.team.toml`, `cortex config`, the machine's `config.toml`, format 3 of the bootstrap, the team's folder renamed, and the development versions: [1.8.0's note](1.8.0.md) tells all of it. Everywhere it says 1.8.0, the first release that has it is 1.8.1. Where that note says a version is "1.8.0 or later", 1.8.1 is one, as are `1.8.0-rc.1` and the development builds of 1.8.0.

## Why 1.8.0 was not published

A release's binary replays the CLI's suite, including tests that only a release runs: a development build, `1.8.0-dev.N`, skips them. The candidate `1.8.0-rc.1` replayed them too, so those tests had run once. Two of them check that `cortex upgrade --team --commit` never commits a developer's own change to the team's file. Their team's file pinned `1.8.0`, and they asked the binary to move it to its own version. At `1.8.0-rc.1` that is a move. At `1.8.0`, the team's file already pins the binary's version, so there is no move and nothing to commit, and the assertions failed on three of the four targets.

The release workflow builds and checks every asset before it creates the draft, so the failure left nothing behind (ADR-009 §3.3). A draft is never rebuilt from another commit, so the fix ships under a new version, in a new pull request:

- **The two tests now pin another version than the binary's**: `1.8.0`, or `1.8.0-rc.1` when the binary is `1.8.0` itself.
- **Before this pull request, the whole CLI suite ran as a binary stamped 1.8.0 and as one stamped 1.8.1**: no other test depends on that version.
- **The README's example of a team's file pins 1.8.1**: no release is named 1.8.0, so `cortex sync` could not download it.

## Upgrading

`cortex self-update`, then `cortex upgrade --all`, or `cortex upgrade --team 1.8.1` in a team's repository. A project on `1.8.0-rc.1` moves the same way. A project that adopts none of 1.8.0's features reads, syncs and validates as before.
