# 🚀 Cortex v1.8.4 — Reality Is Frequently Inaccurate

> *"The Guide is definitive. Reality is frequently inaccurate."* — *The Restaurant at the End of the Universe*
>
> Cortex's own guide had the opposite problem: the remedies it named, and the README's account of what the assistant does, were sometimes less accurate than what Cortex really did. This patch brings them back in line. It also finishes what 1.8.3's reviews left open.

Nothing is added to the `cortex` command. Messages, remedies, the runtime's warnings and the README change.

## Remedies that work from where you are

- **Every update a source checkout names is its own** ([#374](https://github.com/xod-labs/cortex/issues/374)). A `cortex.lock` or a `projects.toml` written by a later Cortex, and the notice of a newer release, used to name `cortex self-update` from a source checkout, which refuses it. They now name `git -C <checkout> pull`. The notice also names the release to upgrade to, since a checkout is a build of no release.
- **A checkout on a detached HEAD** is told `git -C <checkout> pull origin HEAD`, which works there ([#374](https://github.com/xod-labs/cortex/issues/374)).
- **`cortex validate` and a stored version left incomplete** ([#369](https://github.com/xod-labs/cortex/issues/369)): `LOCK_DIGEST` names the removal of that version first, then the sync. It used to name a sync that the store refuses.
- **A file where the team's folder should be, or a link to one**, is named as such, with its remedy. It used to be called a folder that is not there ([#375](https://github.com/xod-labs/cortex/issues/375)).
- **`cortex init DIR`, run from elsewhere, beside a team's folder this user cannot search** names `chmod u+rwx DIR/agents`, the path that works from where it runs ([#375](https://github.com/xod-labs/cortex/issues/375)).

## The runtime and `cortex.local.toml`

- **It says once that it cannot open the file**, and again only when the error changes. It used to warn at every request ([#375](https://github.com/xod-labs/cortex/issues/375)).
- **A directory, or a named pipe, in place of the file** is read as no file, in silence, as `cortex config` reads it ([#375](https://github.com/xod-labs/cortex/issues/375)).

## What the assistant does on its own

The README's table now says every rule of both bootstrap templates, each in exactly one row ([#373](https://github.com/xod-labs/cortex/issues/373)). New rows cover:
- a `cortex.toml` that names another team's folder;
- a `cortex/` link that leads nowhere;
- a sync that names a missing team's folder;
- a sync that refuses a key.

A `version` removed from a file counts as moved.

## Under the hood

#375 also hardens 1.8.3's fixes. It adds the tests their review found missing, kills the mutants that survived, and gives two rules a single home: the runtime's refusal of a service, now public and read by `cortex validate`, and "a link out of every repository is committed nowhere".

## Upgrading

`cortex self-update`, then `cortex upgrade 1.8.4`, or `cortex upgrade --team 1.8.4` for a team's file. A project that stays on 1.8.3 keeps working.
